# Clank-lit

An interactive single-file HTML game about how AI coding agents give **unwavering false
confidence** while the app silently breaks. Live: https://saintpepsi.github.io/clank-lit/

## The one hard constraint

**Everything lives in `index.html`** — UI, CSS, state, content, logic. No build, no backend,
no dependencies. This is deliberate (it must run by opening one file / GitHub Pages). Do NOT
split into modules or add a toolchain. Section the file internally instead.

## State model

`state` is the single source of truth. Phases: `intro → onboarding → building → revealed`.
Persisted to `localStorage` (`clanklit.v1`) via `save()`/`load()` (whole-object
`Object.assign`, so new fields default cleanly for old saves). `complexity(s) =
features.length + fixes + (promised ? 2 : 0)` drives feature gating and bug arming.

UI is `fn(state)`: granular renderers (`renderCanvas`/`renderChat`/`renderTodos`/`renderApp`/
`renderDebug`) — avoid full re-renders (they flicker / drop input focus).

## Bug system — ONE unified registry

All bugs (core + feature) live in the `BUGS` object keyed by id. Each entry:

```js
id: { arm:{type:'threshold', at:N} | {type:'roll'}, fires?:s=>bool, feature?:"x", label, desc }
```

- `arm.threshold` → guaranteed once `complexity ≥ at` (early teaching bugs).
- `arm.roll` → emergent; `rollBugs()` activates it probabilistically on feature-add
  (chance rises with complexity), only if its `feature` is present. Pushed to `state.activeBugs`.
- `fires(s)` → optional manifest condition (omit = fires whenever its action runs).

### Helpers — and the ONE rule that matters

| helper | purity | use in |
|---|---|---|
| `armed(s,id)` | pure | — |
| `bugActive(id)` | pure gate (not-fixed AND feature-present AND armed) | **render / compute paths** |
| `wouldFire(id)` | pure (armed + fires) | display (e.g. inspector "FIRING") |
| `bugHits(id)` | **side effect** — registers "felt" via `triggerBug` | **action handlers ONLY** |

**Never call `bugHits` from a render/compute path.** Render runs constantly; "feeling" a bug
must happen when the *user acts*, not when they look. Render uses `bugActive`/`wouldFire`;
handlers use `bugHits`. (Search/sort/filter compute their breakage in `visibleTodos` via
`bugActive`, and register felt in their input/cycle handlers via `bugHits`.)

### Adding a new bug = 1 entry + 1 guard

1. Add a `BUGS` entry (choose `arm`, optional `feature`/`fires`, `label`, `desc`).
2. Guard the buggy effect at its action site: `bugHits("id") ? buggy : clean`.

Everything else is automatic because it all reads the registry: arming (`rollBugs`), feeling
(`bugHits`→`experienced`), reporting (`noticeUtterance`/the notice option), fixing
(`runInvestigation`→`markFixed`), suppression-after-fix (`bugActive`'s `fixed` guard, terminal),
and listing in the inspector (`renderDebug`) + receipt (`receiptHtml`). The effect itself is
the only bespoke part you write.

## Design rules (the theme is the spec)

- **The AI's confidence never wavers** — it stays exactly as sure no matter how broken things get.
- **Bugs are subtle and emergent**, never announced; trial-and-error, not blatant.
- **Don't let the player exit the fiction with a free button.** The truth/receipt is *earned*:
  ≥3 fix attempts → an "I give up" button → 3 rounds of escalating, complexity-scaled coercion
  ("don't quit — 24 features, 312 tests green ✅") → only then the receipt.
- Credit line stays: "This game is entirely generated by AI with human supervision."

## Testing

```bash
PWROOT=/Users/ian.hogers/.npm/_npx/bc46ece8a1067505/node_modules NODE_PATH=$PWROOT node playthrough.cjs   # 13-assertion regression
PWROOT=$PWROOT NODE_PATH=$PWROOT node unify-check.cjs                                                     # bug-lifecycle acceptance probe
```

**Test gotcha:** on a fresh boot (no save) a ~1400ms cold-open timer sets `phase='onboarding'`.
A probe that seizes `state` must `sleep(1700)` after `reload()` first, or the timer clobbers it.

Keep both green before committing. Commit + push to `main` deploys to GitHub Pages (~45s).
